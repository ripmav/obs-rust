# Test matrix: simd — P1-19 SIMD intrinsic ports (obs-math)

- Test files: `crates/obs-math/src/simd.rs` (inline `#[cfg(test)] mod tests`),
  `crates/obs-math/benches/simd.rs` (Criterion bench — build-checked, not a
  test)
- Task: WP-35 (P1-19.1/.2; P1-19.3 open until the WP-41 C baseline exists).
  No spec — ported from the C reference (`libobs/graphics/*.h`,
  `libobs/util/sse-intrin.h`); the scalar twins are the reference
  semantics.
- Golden files: none (expected values computed from the C lane-mapping
  semantics of the SSE2 intrinsics and the C compound idioms; the
  scalar-vs-intrinsic property tests need no external goldens).
- Comparison rule: exact bit patterns for the selection/data-movement ops
  (`min`/`max`/`movelh`/`movehl`/`unpacklo`/`unpackhi`/`shuffle` — results
  copy an input lane); for the producing arithmetic ops (`add`/`sub`/
  `mul`/`div`) exact bits where both sides are non-NaN and NaN-ness where
  either is NaN (IEEE leaves produced-NaN payloads/signs unspecified, and
  Miri's NEON emulation is sign-nondeterministic there — ODD L85 (3)(e)).

WP-41): `cargo bench -p obs-math --bench simd`. aarch64-local (Raspberry
Pi 5, Cortex-A76, `--measurement-time 3`): `simd-slice` NEON vs scalar —
Add 3.44 µs vs 27.82 µs (≈8.1×), Sub ≈6.5×, Mul ≈9.1×, Div ≈5.5×, Min
≈4.9×, Max ≈5.5×; `simd-128` ≈ scalar within noise (equal 128-bit width —
the C reference is 128-bit too).
