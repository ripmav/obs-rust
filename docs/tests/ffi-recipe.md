# FFI recipe bridges (P1-08.5)

C ABI bridges in `crates/obs-ffi` for the leaf modules ported in Phase 1
(recipe step 2, `docs/rust-rewrite/subtasks/phase-1-subtasks.md`). Each
module bridges every `EXPORT` function of its C header with the exact C
signature; `static inline` helpers stay C-side. Public C structs are
`#[repr(C)]` mirrors; memory the C side frees with `bfree` is allocated
through the C allocator (`bmalloc`/`bstrdup`/`bstrdup_bytes` in
`abi_common.rs`); every `char *` exposed to C is NUL-terminated (the C
dstr invariant — the conformance runners print with `%s`).

| module            | C header             | EXPORT fns                        | bridge                                                                                                                                      | notes                                                                                         |
| ----------------- | -------------------- | --------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------- |
| `abi_text_lookup` | `util/text-lookup.h` | 4                                 | opaque `Box<TextLookup>` handle                                                                                                             | value buffers stored NUL-terminated; `getstr` returns the slice without the NUL               |
| `abi_lexer`       | `util/lexer.h`       | 10                                | `repr(C)` `lexer`/`base_token`/`strref`/`error_data`; the tokenizing core runs over the C-owned buffer                                      | `error_data` growth through the C allocator; NULL file prints `(null)` (glibc `%s`)           |
| `abi_cf_lexer`    | `util/cf-lexer.h`    | 9                                 | `repr(C)` mirrors composed over the base-lexer state; `SPACE_FILLER`                                                                        | `cf_literal_to_str` reuses the obs-util engine helper (C-allocated result)                    |
| `abi_cf_parser`   | `util/cf-parser.h`   | 2 (`cf_adderror`, `cf_pass_pair`) | `repr(C)` `cf_parser` composed from the existing mirrors (size 224: `lex@0`, `pp@72`, `error_list@192`, `cur_token@216`); C owns the struct | row/col from the current token's unmerged text; `$n` substitution leaves NULL params verbatim |

Total: 25/25 C-exported functions bridged.

## Verification

- **Swap builds** (`test/conformance/run.sh swap <area>`): the runner is
  built with the swapped C sources (`lexer.c`, `cf-lexer.c`, `cf-parser.c`,
  `text-lookup.c`, `base.c`) dropped from the source list and
  `target/release/libobs_ffi.a` linked in their place — exactly what
  `OBS_ENABLE_RUST=ON` does in the libobs CMake build
  (`patches/obs-studio-OBS_ENABLE_RUST.patch`). Results on this host
  (aarch64, 2026-11-20): `lexer` 26/26, `serial` 28/28, `config` 11/11,
  `effect` 41/41 (includes the 21-file corpus scripts and the
  `80-quirks` reference-behaviour set) — all byte-identical to the
  committed vectors (which were generated by the C reference).
- **cbindgen drift check** (recipe step 3):
  `bash test/conformance/cbindgen-check.sh` — generates the bridge header
  and compares the exported function set against the four C headers
  (25/25). Skips cleanly when cbindgen is absent.
- Rust-side: `cargo test -p obs-util` (193 lib + 4 + 1),
  `cargo test -p obs-ffi`, clippy (`-D warnings`) host, `cargo fmt`.
- `OBS_ENABLE_RUST` CMake mechanism verified with a shadow project (genex
  source exclusion + imported staticlib resolving the real
  `text_lookup_create` symbol); a full libobs configure needs the complete
  OBS dependency set (FFmpeg 8, …) and is not runnable on this host.

Known pre-existing conformance differences (unrelated to the bridges,
also present in normal C mode on this host): `bmem/02-realloc` (suite
bug), `lexer/03-strref-cmp` (aarch64 `c_char` sign), `signal/08`,
`signal/14` (C-only paths).
