# Phase 0 guide: foundation

Read [00-developer-primer.md](00-developer-primer.md) first. Task list: [../phase-0-foundation.md](../phase-0-foundation.md); subtasks: [../subtasks/phase-0-subtasks.md](../subtasks/phase-0-subtasks.md).

## Purpose

Phase 0 produces no product code. It produces the means to prove, mechanically, that later phases did not change behaviour: decisions in ADRs, a build that links Rust into `libobs`, a reference output generated by the C code, and an ABI test.

## What exists today (so you do not duplicate it)

- **Build:** CMake 3.28+ with presets (`CMakePresets.json`), platform helpers in `cmake/{common,linux,macos,windows}`. `libobs` is built by `libobs/CMakeLists.txt` with OS files `libobs/cmake/os-{linux,macos,windows,freebsd}.cmake`. Module lists come from `libobs/cmake/obs-core-modules.cmake` and `libobs/obs-core-modules.c.in`.
- **Tests:** `test/cmocka/` (four files: `test_bitstream.c`, `test_darray.c`, `test_os_path.c`, `test_serializer.c`) built only with `ENABLE_UNIT_TESTS`; each is a `main()` using `cmocka_run_group_tests`. `test/test-input/` is a real OBS module (`test-input.c`, `test-filter.c`, `test-random.c`, `test-sinewave.c`, `sync-*.c`) built with `BUILD_TESTS`; it registers sources such as a random-pixel source and a sine-wave audio source — use it as the base for the ABI plugin (P0-15) and the A/V sync test (P2-27). `test/win` and `test/osx` hold OS-specific test helpers.
- **CI:** `.github/workflows/` (inspect before editing; names of required checks matter).

## Design notes per task group

### ADRs (P0-01…P0-06)
Write each ADR so a developer who joins in year two understands *why*. Mandatory content: the constraint (e.g. "C plugin ABI, ~1,000 exported symbols"), the options with cost/risk, the decision, and how to revisit it. Measured data beats opinion: attach benchmark numbers (P0-03) and prototype links (P0-04).

- **P0-03 graphics.** Key discovery for the ADR: graphics backends are *loadable modules*. `gs_create()` (`libobs/graphics/graphics.c:198`) does `os_dlopen(module)` and `load_graphics_imports()` fills `struct gs_exports` (`graphics-internal.h:30`) with ~176 function pointers (`device_create`, `device_texture_create`, …). A `wgpu` backend can therefore be a new shared module exporting the same 176 `device_*` symbols, selectable at runtime, **without touching Phase 4**. Say this in the ADR; it removes the biggest ordering risk between Phase 3 and Phase 4.
- **P0-06 concurrency.** Use section 4 of the primer as the starting diagram and complete the lock table (46 mutexes in `obs-internal.h`).

### Cargo + CMake (P0-07, P0-08)
- Workspace at repo root, crates under `crates/`. `Cargo.lock` is committed (binary project).
- Corrosion (`corrosion_import_crate(MANIFEST_PATH …)`) turns a `staticlib` crate into a CMake target. Use **one** aggregate staticlib (`obs-ffi`) that re-exports the others to avoid duplicate Rust runtime symbols when several staticlibs are linked into one binary — this is a classic Corrosion pitfall.
- Windows: Rust staticlibs need the matching CRT (`/MD` vs `/MT`); `cmake/windows` sets the runtime, match it with `-C target-feature` as needed. macOS: build both `x86_64-apple-darwin` and `aarch64-apple-darwin` for universal builds.
- Do not make Rust mandatory yet: `OBS_ENABLE_RUST` defaults to OFF; CI builds both.

### Golden framework and C reference dumper (P0-13, P0-14)
- Goldens must be deterministic: seed the PRNG, print floats with `%.9g` (round-trippable `float`) or hex bits, sort hash-table iteration (`obs_data` uses uthash; iteration order is insertion order in practice but do not rely on it).
- Write the dumper as a normal CMake executable linking `libobs` (like the cmocka tests do). One subcommand per area (`math`, `data`, `calldata`, `audio-mix`, `pixel`), output to stdout.
- Line endings: the `.gitattributes` rule (`*.golden -text`) prevents CRLF conversion. Also make the dumper open stdout in binary mode on Windows.

### ABI plugin test (P0-15)
Model a minimal module on an existing one. `plugins/obs-filters/gain-filter.c` is ~100 lines and shows the entire pattern:

```c
struct obs_source_info gain_filter = {
    .id = "gain_filter", .type = OBS_SOURCE_TYPE_FILTER, .output_flags = OBS_SOURCE_AUDIO,
    .get_name = gain_name, .create = gain_create, .destroy = gain_destroy,
    .update = gain_update, .filter_audio = gain_filter_audio,
    .get_defaults = gain_defaults, .get_properties = gain_properties,
};
```
registered inside `obs_module_load()` with `obs_register_source(&gain_filter)`. Note `obs_register_source` is a macro over `obs_register_source_s(info, sizeof(*info))` (`libobs/obs-module.c:1035`): libobs copies only `min(size, sizeof(known))` bytes, which is how old plugins keep working when fields are appended. Your ABI test must include a plugin compiled against an *older* (smaller) struct to prove the Rust loader copes. Trace each callback by logging `(callback name, thread id, order)` into a text file and compare it with goldens.

### Smoke test (P0-16)
Use the null/software path available on CI. Without a GPU, libobs graphics init fails; the headless test therefore needs either Xvfb + Mesa llvmpipe (OpenGL backend, Linux) or a WARP adapter (D3D11, Windows). Check how the existing `test/test-input` is exercised and whether any current CI job already runs libobs headlessly before inventing a new mechanism.

### Corpus (P0-18)
Scene collections are JSON; secrets to strip: stream keys (`key` in `service.json`), URLs with tokens (browser sources), window titles, absolute file paths. Keep a mapping from original to placeholder so the structure stays valid.

## Pitfalls

- Corrosion + `cdylib` module crates (Phase 5) need different crate types than the aggregate `staticlib`; plan the crate-type matrix now.
- `cbindgen` cannot express every C macro (`OBS_DECLARE_MODULE`, `da_*`). Treat the existing headers as the source of truth and generate Rust bindings *from them* (e.g. `bindgen` in a test crate) to cross-check, instead of generating headers from Rust.
- Clippy `-D warnings` on a fresh workspace is cheap; on a mature one it is painful. Turn it on in P0-09 before any code lands.

## Verification checklist for the phase

- [ ] `cmake --preset ubuntu -DOBS_ENABLE_RUST=ON` and `=OFF` both build and pass `ctest`.
- [ ] `obs-ref-dump` output reproduces byte-for-byte across two runs and across OSes.
- [ ] ABI plugin passes on the C `libobs`.
- [ ] Benchmarks stored; regression gate demonstrated on a deliberate slowdown.
