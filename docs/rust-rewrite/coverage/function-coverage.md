## Method

Every function definition in the tracked source files (incl. initialized submodules) is inventoried; a function is **non-trivial** when its body spans >= 5 lines (one-line getters/setters and similar helpers are counted separately and excluded from the headline numbers — they do not need individual coverage).

Measurement limits (verified in the round-5 audit, 2026-11): macro-generated functions are invisible to ctags (e.g. `DEFINE_VOID_DATA_CALLBACK` in `obs-scripting-lua-source.c` generates 4 callbacks that never appear here — the porting subtasks list them explicitly); body measurement resolves `#if/#else` to one branch and can fail on exotic constructs (a handful of rows stay unmeasured and count as non-trivial); C++ method extraction was verified on samples, not exhaustively; name matching is by identifier, so two different symbols with the same name can collide.

| Flag | Meaning |
|---|---|
| T1 | function name appears in the plan (phase/subtask/guide/plan docs) |
| F1 | function's file is explicitly named in the plan text (stronger than T2's matrix rule, which may be a `*` glob) |
| T2 | function's file has a row in `coverage-matrix.md` (task assigned) |
| S1 | function name appears in a spec (`specs/S-*.md`) |
| S2 | function's file is cited in a spec |
| X1 | function name appears in the conformance corpus (`test/conformance/`) |
| X2 | function's file is referenced in the conformance corpus |
| any1 | T1 or S1 or X1 — the function is named by at least one artefact |
| any2 | T2 or S2 or X2 — the function's file is covered by at least one artefact |
| all2 | T2 and S2 and X2 — task, spec and test all reach the file |
