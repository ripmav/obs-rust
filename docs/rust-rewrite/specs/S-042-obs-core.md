## 1. Scope

The *core context* is the single process-wide object (`obs`) that owns every other libobs object:
registries of source/output/encoder/service types, tables of live objects, the signal and proc
handlers, the graphics device, the video mixes, the audio output, the hotkey subsystem, the task
queues and the main canvas. This spec covers:

* process lifecycle: startup, shutdown (ordering, leftover accounting), locale, version, command-line
  arguments, data-path search, profiler name store;
* `obs_reset_video` (validation, alignment, graphics bring-up, per-format mix setup, canvas restore)
  and `obs_reset_audio2` (validation, buffering arithmetic);
* the canvas object (create/load/save/destroy, names, flags, channels, per-canvas video, source
  membership), the view (channel set + mixes) and the display (swap-chain based preview with draw
  callbacks);
* type registries as *read* by the enumeration APIs, and the object tables with lookup by name/UUID,
  enumeration, name de-duplication and the generic object accessors;
* task queues, tick/draw callbacks, core private data, output protocol list.

Out of scope (separate specs or not covered, see 11): the registration functions themselves (S-035),
the graphics thread frame loop (`obs-video.c`), the audio mixing loop (`obs-audio.c`), source/output/
encoder/service object internals, scene items, hotkey internals, audio monitoring, GPU encoding, the
Windows/macOS specifics.

Callers: the frontend and every plugin (public API); the module loader (registration); sources and
outputs (context-data helpers, task queues, signals).

## 2. Terminology and conventions

RFC 2119 words apply. `W` = 8. "Core" = the object created by `obs_startup`. "Reference" = the C
implementation. A *context* is the common header (`obs_context_data`) of sources, outputs, encoders,
services and canvases. "Public" means not private. Strong reference counts in the vectors are printed as
the raw counter, **owners minus one** (`strong=0` is one owner). Video sizes use `WxH`.
Floating point values in vectors are printed with `%.9g`; compare exactly except that `-0` equals `0`.
UUIDs generated by the core are random (36 chars, `8-4-4-4-12` lower-case hex); the vectors mask them.

## 4. Data formats

No byte-level formats. Persisted canvas record (an `obs_data` object): keys `name` (string), `uuid` (string), `private` (bool),
`flags` (int; the internal REMOVED bit never appears because removed canvases are not saved). Example for a public canvas created
with `PROGRAM`: `{"name":"Alpha","uuid":"<36 chars>","private":false,"flags":14}`.

Colour matrix stored per mix (16 floats, row-major as laid out by the 4x4 matrix type): for YUV output formats
`M = swap_rows_0_1(inverse(P))` where `P` is the RGB-to-YUV matrix for (colorspace, range, format) defined by S-013; for every
other format `M = identity`. Worked values are in `025_video_mix_formats` (e.g. NV12/709/partial:
`-0.100643739 -0.338571936 0.43921569 0.501960754 / 0.18258588 0.614230573 0.0620070584 0.0627451092 / 0.43921569 -0.398942143 -0.0402735248 0.501960814 / -0 0 -0 1`).
YUV formats (for this purpose): I420, NV12, I422, I210, YVYU, YUY2, UYVY, I444, I412, I40A, I42A, YUVA, YA2L, AYUV, I010, P010, P216, P416, V210.
Non-YUV: None, RGBA, BGRA, BGRX, Y800, BGR3, R10L.

## 5. Behaviour (numbered rules)

### 5.1 Startup and shutdown

* **S-042-R01** `obs_startup` while a core exists logs a WARNING ("Tried to call obs_startup more than once"), returns `false`, and
  changes nothing.
* **S-042-R02** A successful `obs_startup` yields a core with: no graphics device, no video mixes, no audio output, empty object
  tables, the 32 signals of 3.3 declared, an empty proc handler, hotkey subsystem started, the main canvas (R40) created, the
  destruction task queue running, a copy of `locale` and (when given) of `module_config_path` (NULL is accepted for both and stays
  NULL), and the unnamed-object counter at 0. Exactly three source types are registered, in this order: `scene`, `group`, `audio_line`
  (so `obs_enum_source_types` lists those three and `obs_enum_input_types` lists only `audio_line`). `core_modules_loaded` is false.
* **S-042-R03** Profiler name store: if a store is passed it is used and is **not** freed by shutdown (caller owns it); if NULL the
  core creates one and frees it at shutdown. `obs_get_profiler_name_store` returns the active store.
* **S-042-R04** If any step of startup fails (the vectors exercise failure of hotkey platform initialisation), the core is torn down
  with the normal shutdown sequence, `obs_startup` returns `false` and `obs_initialized()` is false. A failed attempt leaves nothing
  behind: a later startup succeeds.
* **S-042-R05** `obs_shutdown` order (observable through logs and fake-device events): wait for the destruction queue (only when
  video thread and audio output both exist) -> free registered type arrays (calling `free_type_data` for sources/outputs/encoders/
  services that have both `type_data` and a destructor; source type ids are freed) -> stop video outputs and join the graphics thread
  -> close the audio output -> stop the hotkey thread and free hotkey state -> unload modules -> *free context data* (R06) -> free
  audio state -> free video mixes -> destroy the destruction queue -> free hotkey strings/name map/platform -> destroy graphics
  resources and the device -> destroy proc and signal handlers -> free module paths, safe/disabled module lists -> free the owned
  name store, module config path, locale -> clear the core pointer -> free the saved command-line arguments.
* **S-042-R06** Freeing context data logs INFO "Freeing OBS context data", then in this order: releases the main canvas
  (canvas destroy signals fire, R41), destroys every output, encoder, display, service (list heads, one by one), every public source
  (name table), every source (UUID table), every public canvas (name table), every canvas (UUID table). After each group that was
  non-empty it logs INFO "`<N> <kind>(s) were remaining`" where kind is `output encoder display service source canvas`
  (the source and canvas groups can therefore be logged twice: public first, then the private rest).
* **S-042-R07** Remaining video mixes that are attached to a view are counted; if there are any, shutdown (and video reset) logs
  WARNING "Number of remaining views: N".
* **S-042-R08** `obs_initialized()` is true exactly while the core exists. Shutdown followed by startup yields a fresh core
  (counters, registries and handlers restart).
* **S-042-R09** `obs_get_version()` returns the packed API version (3.1); `obs_get_version_string()` a non-empty string.
* **S-042-R10** `obs_set_locale(l)` replaces the stored copy (NULL allowed); every loaded module that has a `set_locale` entry is
  called with `l`. `obs_get_locale()` returns the stored string or NULL.
* **S-042-R11** `obs_set_cmdline_args(argc, argv)`: if the stored `argc` is non-zero the call is ignored; otherwise all strings are
  copied into one block, `argv[argc]` is NULL. `obs_get_cmdline_args()` returns the stored pair (`{0, NULL}` initially).
  The arguments are process-wide (not part of the core) and survive `startup`/`shutdown` cycles *as a count* - see D-1.
* **S-042-R12** Data path search: `obs_add_data_path` appends a copy; `obs_remove_data_path` removes the first exactly equal entry and
  returns true, else false. `obs_find_data_file(f)` tries the platform data directory first; if that does not contain `f` it tries,
  in insertion order, `path + f` (plain concatenation, **no separator**, so paths must end in `/`, Q-2) and returns the first existing
  one (new string); otherwise it logs ERROR "Failed to find file '`f`' in libobs data directory" and returns NULL. The list is not
  part of the core and persists across startup/shutdown.

### 5.2 Video reset

* **S-042-R20** `obs_reset_video(ovi)` returns, evaluated in this order: `FAIL` if no core; `CURRENTLY_ACTIVE` if **any** video
  mix (main or auxiliary) has a raw consumer or a GPU encoder active (before any other check; the struct is not touched);
  `INVALID_PARAM` if any of output width/height or base width/height is outside `[2, 32768]` (nothing is torn down, struct untouched).
* **S-042-R21** After validation the previous state is torn down *before* anything else can fail: video outputs stopped and the graphics
  thread joined, all canvas mixes cleared (R22/D-4), all mixes freed, mutexes recreated, queued graphics tasks discarded.
* **S-042-R22** The caller's struct is then modified in place: `output_width &= ~3`, `output_height &= ~1`. This happens on every path
  that passes R20, including later failures. Consequence (Q-1): output width 2 or 3 becomes 0 and fails later (R26).
* **S-042-R23** The graphics device is created only if none exists: asks the factory for (`graphics_module`, `adapter`). Error mapping:
  `GS_ERROR_MODULE_NOT_FOUND -> OBS_VIDEO_MODULE_NOT_FOUND`, `GS_ERROR_NOT_SUPPORTED -> OBS_VIDEO_NOT_SUPPORTED`, any other non-zero
  `-> OBS_VIDEO_FAIL`. On any failure of graphics set-up (including R24) the graphics resources are released, the device is destroyed,
  and the code is returned; the next reset starts from scratch. Once a device exists, later resets **do not** re-create it or the
  effects (Q-10): `graphics_module`/`adapter` of later calls are ignored.
* **S-042-R24** Graphics set-up, in order, inside a graphics context: locate and compile the effects `default`, (`default_rect`
  only if the device type is OpenGL), `opaque`, `solid`, `repeat`, `format_conversion`, `bicubic_scale`, `lanczos_scale`, `area`,
  `bilinear_lowres_scale`, `premultiplied_alpha` (each `NAME.effect`; all are attempted even after a failure; a missing data file
  logs the R12 error and gives a NULL effect); create a point sampler (max anisotropy 1, other fields zero); create a 2x2 RGBA
  transparent texture (1 level, zero data, no flags). Success requires: `default`, `default_rect` (OpenGL), `opaque`, `solid`,
  `format_conversion`, `premultiplied_alpha`, the texture and the sampler. `repeat`, `bicubic`, `lanczos`, `area`, `bilinear_lowres`
  are optional (their `obs_get_base_effect` result is then NULL). Failure code is `OBS_VIDEO_FAIL`.
* **S-042-R25** After graphics: log INFO block "video settings reset" (base size, output size, scale-type name `Disabled|Point|Bicubic|
  Bilinear|Lanczos|Area`, fps `n/d`, format name, YUV colourspace/range for YUV formats else "None"), notify the source profiler,
  then initialise video (R26).
* **S-042-R26** Initialising video: `frame_interval_ns = muldiv64(1e9, fps_den, fps_num)`, `half_frame_interval_ns = muldiv64(5e8, fps_den,
  fps_num)` (integer, truncating: 30000/1001 -> 33366666 / 16683333; 1/3 -> 3e9; 1e9/1 -> 1 / 0); recreate the video task/encoder-group/mixes
  mutexes; reset the main canvas video (its mix is first in the mix list); restore every *other* canvas (R57); start the graphics
  thread; mark it initialised; emit the core signal `video_reset` (empty parameters). Failure of the main mix or of a restored
  canvas returns `OBS_VIDEO_FAIL` (the device and effects are kept, state: `graphics=yes mixes=0`) - the finer
  `INVALID_PARAM` of the output open is swallowed (e.g. `fps_den = 0`, or width/height 0 after alignment). `fps_num = 0` must give
  `INVALID_PARAM` (D-2: the reference crashes with a division by zero).
* **S-042-R27** Per-mix set-up (`obs_create_video_mix`, used for the main canvas, canvases and views): copies the info; if mixes
  already exist and the main canvas has a mix, the mix's fps is **replaced by the main mix's fps** (auxiliary mixes follow the main
  clock); opens the video output (validation: width, height, fps_num, fps_den all non-zero, else INVALID_PARAM -> log ERROR
  "Invalid video parameters specified" and NULL mix); sets `gpu_conversion` from the request and clears the activity flags; computes
  the colour matrix (4); runs GPU-conversion set-up if requested (R28) and texture creation (R29). Any failure frees the mix and
  returns no mix.
* **S-042-R28** GPU conversion (only when `gpu_conversion` is requested): formats with a converter are I420, NV12, I444, I010, P010,
  P216, P416. For other formats the request is silently dropped (`gpu_conversion=false`, INFO "GPU conversion not available for
  format: N", INFO "NV12 texture support not available"). Otherwise: `using_nv12_tex = (format == NV12) && device supports NV12`,
  `using_p010_tex` likewise; INFO lines "NV12|P010 texture support enabled|not available" are logged for both; techniques and 1/size
  factors are in 6.2; shared NV12/P010 textures (one pair, render target + shared flags 64|4 = 68) are created when the capability
  applies, followed by the plane textures of 6.2.
* **S-042-R29** Texture creation per mix: for `NUM_TEXTURES = 2` iterations: with GPU conversion the plane staging surfaces of 6.2,
  otherwise one staging surface (output size, texture format `F`). Then a render texture (base size, `F`, 1 level, render-target flag 4)
  and an output texture (output size, `F`, render-target). `F` is RGBA16F for I010, P010, I210, I412, YA2L, P216, P416, else BGRA.
  `render_space` = `709-extended` when the colourspace is 2100-PQ or 2100-HLG, else `sRGB-16F` for I010, P010, P216, P416, else `sRGB`
  (numeric 2, 1, 0 in the vectors' `render_space` field: 0 = sRGB, 1 = sRGB-16F, 2 = 709-extended). Any creation failure frees
  everything created so far for that mix and fails the mix (R27).
* **S-042-R30** `obs_video_active()` is true iff any mix in the list has `raw_active > 0` or `gpu_encoder_active > 0`.
* **S-042-R31** `obs_get_video_info(ovi)` returns false if there is no device or the main canvas has no mix; otherwise copies the
  main mix's info (alignment applied; for the main mix fps is exactly as requested).
* **S-042-R32** Levels: `obs_get_video_sdr_white_level` / `..._hdr_nominal_peak_level` return the defaults 300 / 1000 while no graphics
  device exists; with a device they return the stored values, which start at **0** (Q-8) until `obs_set_video_levels(sdr, hdr)`
  (requires a device) stores both. The stored values survive later successful resets, and a failed reset that keeps the device.
* **S-042-R33** `obs_get_base_effect(id)` returns the effect created in R24 (NULL when absent or for an unknown id). Effects
  are rebuilt only with the device (R23).
* **S-042-R34** A successful reset emits, for each canvas that receives a mix in R26 in that order (main first, then the others in
  canvas-table order): core signal `canvas_video_reset(canvas)` (non-private canvases only) and canvas signal `video_reset(canvas)`;
  after all, the core signal `video_reset`.

### 5.3 Audio reset

* **S-042-R35** `obs_reset_audio2(oai)`: returns false if no core, or if the audio output exists and is *active* (has a connected
  consumer); in that case nothing changes (not even when `oai` is NULL). Otherwise existing audio state is freed; a NULL `oai` then
  returns `true` leaving no audio output.
* **S-042-R36** Buffering: if `max_buffering_ms != 0`: `frames = max_buffering_ms * samples_per_sec / 1000` computed in **32-bit unsigned**
  arithmetic (wraps, Q-5), `ticks = (frames + 1023) / 1024`; else `ticks = 45`. `fixed_buffering` is stored. The logged and
  reported milliseconds are `ticks * 1024 * 1000 / samples_per_sec` in integer arithmetic (the default at 48 kHz is 960, at 44.1 kHz
  1044, 1000 ms at 44.1 kHz -> 1021). Requests whose tick count exceeds 2097 overflow the signed `int` in the reference (D-5); a
  conforming implementation must use 64-bit arithmetic for the *reported* value and the wrap of the 32-bit *tick* computation is kept.
* **S-042-R37** The output is opened with name "Audio", format float-planar, the given sample rate and speaker layout. Validation (by
  the output): format, name non-null, `samples_per_sec > 0`, `speakers > 0`; failure logs ERROR "Invalid audio parameters specified"
  and the call returns false with **no audio output** left (the buffering fields and the monitoring defaults of R38 stay set).
  A zero sample rate must return false (D-3: the reference divides by zero in R36 first).
* **S-042-R38** Each (re)initialisation of audio: logs the INFO block "audio settings reset" (rate, speakers as number, max
  buffering ms, "fixed" or "dynamically increasing"), sets the monitoring device to name "Default" / id "default", queues the
  audio-thread marker task, declares the core signal `deduplication_changed(ptr source)` and connects the monitoring-deduplication
  handler (Q-4: repeated resets log WARNING "Signal declaration 'deduplication_changed' exists" and add another connection).
* **S-042-R39** `obs_reset_audio(oai)` is `obs_reset_audio2` with the two fields and default buffering (NULL `oai` is a precondition
  violation). `obs_get_audio_info(out)` returns false for NULL `out` or without audio; else writes rate and layout.
  `obs_get_audio_info2` additionally writes `fixed_buffering` and the derived milliseconds of R36. Both leave `out` untouched on false.
  Freeing audio state (also by a reset) clears everything, including monitoring device strings (shown NULL after
  `obs_reset_audio2(NULL)`).

### 5.4 Canvas

* **S-042-R40** The main canvas: name `Main`, UUID `6c69626f-6273-4c00-9d88-c5136d61696e`, flags `MAIN|PROGRAM` (15), main view type, no
  video until the first successful `obs_reset_video`; public (listed by `obs_enum_canvases`, found by name/UUID). It is created before
  the first video reset and lives until shutdown; it can not be renamed, removed (the call is ignored, `removed` stays false) or video-reset through the canvas API
  (false), and `obs_canvas_save` of it works (name, uuid, private false, flags 15).
* **S-042-R41** Canvas creation (`obs_canvas_create`, `_private`, load): the `MAIN` flag is always cleared from the requested flags; a
  context is built (name made non-blank by R70, UUID: the supplied one only if exactly 36 characters, else generated); the eight canvas
  signals of 3.3 are declared; the view type is `main` iff `ACTIVATE` is set; if video info is given a mix is created (R27) and, on
  success, bound to the canvas view with `mix_audio = flags & MIX_AUDIO`, appended to the mix list; the stored `ovi` is the *requested*
  info even if the mix failed; the canvas is inserted into the UUID table (a UUID already present is replaced by a fresh one with a WARNING
  `Attempted to insert context with duplicate UUID "<uuid>"!`); if public it is also inserted into the name table (duplicate names get a
  suffix, R70) and the core signal `canvas_create(canvas)` fires; finally DEBUG `[private ]canvas 'NAME' (UUID) created`.
  A failed mix does not fail the canvas.
* **S-042-R42** Reference counting: creation returns one strong reference. `obs_canvas_get_ref` returns the canvas with one more strong
  reference or NULL when the canvas is already dead. The last release destroys it (R43). `obs_canvas_release` with no core logs
  WARNING "Tried to release a canvas when the OBS core is shut down!" and does nothing; NULL is ignored. Weak references: a weak handle
  does not keep the canvas alive; `obs_weak_canvas_get_canvas` returns a new strong reference or NULL once dead; weak handles are freed
  when their own count reaches zero.
* **S-042-R43** Destruction: core signal `canvas_destroy(canvas)` (public canvases only) then canvas signal `destroy`; the mix is removed
  from the list and freed; scenes held strongly by a `SCENE_REF` canvas are released; the canvas is removed from the UUID table and (if
  public) the name table; DEBUG `... destroyed`; the view is freed (all its channels deactivated and released).
* **S-042-R44** `obs_canvas_set_name(c, name)`: ignored if `name` is NULL or empty, if the canvas is `MAIN`, or if equal to the current
  name. Otherwise: private canvases take the name as is (no uniqueness); public ones are re-keyed with de-duplication (R71). The old
  name is remembered; canvas signal `rename(canvas, new_name, prev_name)` fires, then, for public canvases only, the core signal
  `canvas_rename(canvas, new_name, prev_name)`.
* **S-042-R45** `obs_canvas_remove(c)`: ignored for `MAIN` and already removed canvases; otherwise (with a strong reference held during
  the call) sets the REMOVED flag (bit 31), fires core `canvas_remove(canvas)` (public only) then canvas `remove`. No reference is
  dropped, the canvas stays listed and findable. `obs_canvas_removed` reports the flag.
* **S-042-R46** Save/load: `obs_save_canvas` returns NULL for canvases with `EPHEMERAL` or `REMOVED`, else the record of section 4.
  `obs_load_canvas(data)` creates a canvas *without video* from those keys (flags truncated to 32 bits, `MAIN` stripped; a stored UUID
  that is not exactly 36 characters is replaced by a generated one); it respects the stored `private` flag.
* **S-042-R47** `obs_canvas_reset_video(c, ovi)`: false for NULL `ovi`, `MAIN` canvases, and canvases that are video-active (R49);
  otherwise `R48` with the given info and returns whether a mix exists afterwards.
* **S-042-R48** Canvas video reset (internal): the old mix is removed from the list and freed (always, even if the new one fails); the
  info is stored; a new mix is created (R27, **no size validation and no alignment** - only the output's own checks), bound to the
  canvas view with `mix_audio` from flags, appended at the **end** of the mix list; core `canvas_video_reset` (public only) and canvas
  `video_reset` fire (also when the mix could not be created). A failed reset leaves the canvas with the new (maybe invalid) info and no mix.
* **S-042-R49** `obs_canvas_video_active(c)` is true iff the canvas has a mix present in the list with `raw_active > 0` or
  `gpu_encoder_active > 0`; false for NULL or mixless canvases. `obs_canvas_has_video` is `mix != NULL`;
  `obs_canvas_get_video` the mix' video output or NULL; `obs_canvas_get_video_info` copies the *mix* info (so with the main fps) and
  returns false without device or mix. A stored info is "valid" (internal) iff base and output sizes are non-zero and the format is not None.
* **S-042-R50** Channels (`obs_canvas_set_channel`, 64 slots, index >= 64 is a precondition violation): under the view lock a strong
  reference to the new source is taken; if it equals the current one the reference is dropped and nothing else happens (no signal).
  Otherwise the canvas signal `channel_change(canvas, channel, prev_source, source)` and, for the `MAIN` canvas only, the core signal
  `channel_change` with the same parameters fire; a handler may replace `source` (in/out parameter) and the replaced value is stored;
  after unlocking the new source is activated for the view type, the previous one deactivated and its reference dropped.
  `obs_canvas_get_channel` returns a new reference or NULL. `obs_get_output_source/obs_set_output_source` act on the main canvas.
* **S-042-R51** Source membership (`obs_canvas_insert_source` / `obs_canvas_remove_source` / `obs_canvas_rename_source`): insertion into a
  `SCENE_REF` canvas takes an extra strong reference for scene (and group) sources; a source that already belongs to a canvas is first
  removed from it; the source keeps a weak reference to the canvas; the name is inserted into the canvas' own name table with de-duplication
  (R70) and canvas signal `source_add(canvas, source)` fires. Removal drops the weak reference, removes the name, fires `source_remove`,
  drops the scene reference of `SCENE_REF` canvases, removes a group from the scenes of that canvas, and clears the source' canvas.
  Rename re-keys within the canvas (R71), fires the source' own `rename`, the canvas' `source_rename` and, for the `MAIN` canvas, the core
  `source_rename`. Scenes and groups of canvases are **not** in the core's public-source table.
* **S-042-R52** `obs_canvas_get_scene_by_name(c, name)`: lookup in the canvas' table; returns the scene object or NULL (the temporary
  reference is dropped when the source is not a scene); `obs_canvas_enum_scenes` visits canvas sources of scene type in insertion order and
  stops when the callback returns false.

### 5.5 View

* **S-042-R53** `obs_view_create` yields an auxiliary view with 64 empty channels. `obs_view_set_source/get_source`: NULL views are
  ignored (get -> NULL); under the lock the new source is referenced and stored, the previous one is deactivated and released;
  `get_source` returns a new reference. The same source may occupy several channels. Index >= 64 is a precondition violation.
* **S-042-R54** `obs_view_render` renders the channels in index order (sources marked removed are released and their channel cleared
  **without** deactivation, Q-11). `obs_view_destroy` deactivates and releases every channel, then frees the view; NULL is ignored.
* **S-042-R55** `obs_view_add(view)` uses the main canvas' mix info and returns NULL if the main canvas has no mix; `obs_view_add2(view, ovi)`
  returns NULL for NULL view/info; both create a mix (R27 - fps follows the main mix, no alignment), bind it to the view, append it to
  the mix list and return its video output, or NULL when mix creation fails. `obs_view_remove` clears the view binding of every mix bound
  to that view (mixes remain). `obs_view_enum_video_info` visits mixes bound to the view in list order, stops when the callback returns false.
* **S-042-R56** Mix list order: main mix first (after any reset), then others in creation/reset order; a canvas video reset moves its
  mix to the end (R48).
* **S-042-R57** Restoring after a main reset: every non-main canvas whose stored info is valid (R49) gets a new mix from its stored info
  (fps replaced by the main fps, R27). Failure of any restore fails the whole reset (R26). Canvases without valid info are skipped.
  **Private canvases are skipped, their old mix is freed without clearing the canvas' pointer** (D-4: required behaviour: private
  canvases are cleared/restored/signalled exactly like public ones).

### 5.6 Display

* **S-042-R58** `obs_display_create(init_data, bg)`: inside a graphics context creates a swap chain from `init_data` (if not NULL;
  failure logs ERROR "obs_display_init: Failed to create swap chain" and returns NULL, registry unchanged) and records `cx = next_cx =
  init_data.cx` (0 without data); the display starts enabled; the new display is inserted at the **head** of the display list.
  Requires an existing graphics device (precondition).
* **S-042-R59** `resize(d, cx, cy)` only stores `next_cx/next_cy`. `size(d, &w, &h)` reports the size of the last *rendered* frame
  (initially the creation size); a NULL display reports 0x0. `update_color_space` sets a pending flag. All NULL-display calls are no-ops
  (`enabled(NULL)` is false).
* **S-042-R60** `render_display(d)`: nothing if NULL or disabled. Otherwise, atomically reads and clears the pending flag and reads
  `next_cx/next_cy`; loads the swap chain; if the pending size differs from `cx/cy` the device is resized and `cx/cy` updated,
  **else if** the colour-space flag was set the device colour space is refreshed (so a refresh requested together with a resize is dropped,
  Q-7); if the device reports it is ready to present: begin scene, clear depth+stencil+colour with the colour of R61 (depth 1, stencil 0),
  depth test off, culling off, orthographic projection `(0, cx, 0, cy, -100, 100)` (arguments in that order), viewport `(0,0,cx,cy)`,
  call every draw callback in registration order with `(cx, cy)`, end scene, present. If not ready nothing is drawn (swap chain still loaded).
* **S-042-R61** Clear colour: `bg` is `0xAABBGGRR`-packed (R in the lowest byte) and converted to floats /255; on a device whose
  colour space is sRGB the colour is used as is, on any other colour space it is converted from sRGB to linear first; alpha is forced to 1.
  Example: `0xff102030 -> (0.188235298, 0.125490203, 0.0627451017, 1)`, `0x80ff8040` with an sRGB device -> `(0.250980407, 0.501960814, 1, 1)`.
* **S-042-R62** Draw callbacks: `add` appends (order = invocation order); `remove` erases the first entry equal in function *and* parameter.
  `set_enabled`, `set_background_color` store; `enabled` reads.
* **S-042-R63** `obs_display_destroy` unlinks from the list, frees the swap chain inside a graphics context; shutdown destroys remaining
  displays in list order (newest first) and logs R06.

### 5.7 Registries, enumeration and lookup

* **S-042-R70** Context names: a missing or empty name becomes `__unnamed` + zero-padded 4-digit counter value (`__unnamed0000`), the counter
  being **shared by all object kinds** and starting at 0 with each core; a *private* object with a **NULL** name keeps a NULL name (an empty
  string still gets a generated one). For hash-table insertion of public objects (sources, canvases, canvas sources) a name already present
  is replaced by the first free of `"<name> 2"`, `"<name> 3"`, ... (suffix tried against the table, which includes already suffixed names:
  inserting `Alpha 2` when `Alpha` and `Alpha 2` exist yields `Alpha 2 2`); WARNING `Attempted to insert context with duplicate name "<name>"! Name has been
  changed to "<new>"`. Outputs, encoders and services are not de-duplicated.
* **S-042-R71** Renaming within a table: the object is removed from the table, the old name is kept alive in a rename cache, the new name is
  de-duplicated against the others (the object itself no longer counts, so renaming `b` (currently `One 2`) to `One` while `a` is `One` gives `One 2` again, and the rename signals still fire), WARNING `Attempted to rename context to duplicate name "<OLD name>"! New name has been changed to "<new>"`
  (the text shows the object's *old* name, Q-3), and the object is re-inserted. A rename request equal to the current name of a canvas is
  filtered earlier (R44); sources have no such filter.
* **S-042-R72** Registry enumeration `obs_enum_*_types(idx, &id)`: returns false for `idx >= count` without touching the output;
  otherwise the id of the entry in registration order. `source` = all registered source types (global list), `input`/`filter`/
  `transition` = per-category lists (scene types are only in the global list). `obs_enum_input_types2` writes `id` and/or
  `unversioned_id` only where the pointer is non-NULL. A source type registered with version `v != 0` has the id `"<id>_v<v>"` and keeps
  `<id>` as unversioned id; version 0 uses the plain id for both.
* **S-042-R73** `obs_get_latest_input_type_id(u)`: NULL for NULL `u`; otherwise scans *all* source types in order for `unversioned_id == u`
  and returns the id of the highest version (first wins on ties; version 0 beats "none"). An unknown `u` is a precondition violation
  (assert); a conforming implementation returns NULL.
* **S-042-R74** Object lists: outputs, encoders and services are singly-owned lists with **insertion at the head**; their enumeration
  visits newest first and **includes private objects**; sources are enumerated in UUID-table order (= creation order). A callback
  returning false stops the walk; the table lock is held during callbacks.
* **S-042-R75** `obs_enum_sources`: visits sources that are public and either of input type or the `group` type (not scenes, filters,
  transitions, private sources); each visited source is held with a temporary reference. `obs_enum_all_sources` visits every source in
  UUID-table order, private ones included, without taking references. `obs_enum_scenes` = `obs_canvas_enum_scenes(main canvas)`.
  `obs_enum_canvases` visits **public** canvases in name-table order (creation order, main first); private canvases are never listed.
* **S-042-R76** Lookup by name: `obs_get_source_by_name` searches the public-source table, then (compatibility fallback) the main canvas' source
  table; private sources are never found; result has one new reference. `obs_get_canvas_by_name` searches public canvases;
  `obs_get_{output,encoder,service}_by_name` scan the list newest-first, skip private entries and take the first equal name.
  `obs_get_transition_by_name` scans **all** sources (UUID order, oldest first, private included) for a transition with that name.
  A dying object (strong count already below zero) is not returned.
* **S-042-R77** Lookup by UUID (`obs_get_source_by_uuid`, `obs_get_canvas_by_uuid`) searches the UUID tables and finds private objects;
  `obs_get_transition_by_uuid` returns the source only if it is a transition (else it releases it and returns NULL).
  Sources/canvases built with a duplicate or short UUID get fresh ones (R41; sources: duplicate -> fresh UUID with the same WARNING).
* **S-042-R78** `obs_get_main_canvas` returns the main canvas with a new reference.
* **S-042-R79** Generic accessors on any context pointer: `obs_obj_get_type` -> the context type or `INVALID` for NULL; `obs_obj_get_id` ->
  the type id for sources, outputs, encoders, services and NULL for canvases/NULL; `obs_obj_invalid` -> true for NULL or when the object has no
  private data pointer; `obs_obj_get_data` -> that pointer or NULL; `obs_obj_is_private` -> false for NULL.
* **S-042-R80** `obs_reset_source_uuids`: under the sources lock every source (private included) receives a fresh random UUID and the UUID
  table is rebuilt from scratch; iteration order stays creation order; lookups by the old UUID fail afterwards.
* **S-042-R81** Output protocols: `obs_is_output_protocol_registered(p)` is an exact, case-sensitive compare against the protocol list;
  `obs_enum_output_protocols(idx, &p)` returns false past the end. (Protocols are appended by output registration, S-035.)
* **S-042-R82** Object reference helpers: `obs_object_get_ref` returns the object with one more strong reference or NULL (NULL object or dead);
  `obs_object_release` with no core logs WARNING "Tried to release an object when the OBS core is shut down!"; the last release calls the
  object's destroy callback and drops the control block's own weak reference. Weak helpers: `expired` (true for NULL), `references_object`
  (false for NULL arguments).

### 5.8 Tasks, callbacks, private data

* **S-042-R83** `obs_queue_task(type, task, param, wait)`: `UI`: calls the registered UI handler `(task, param, wait)` or logs ERROR "UI task
  could not be queued, there's no UI task handler!" (task dropped). Other types: if the caller is on the target thread the task runs inline;
  else with `wait` the call queues a signalling wrapper and blocks until it ran; else the task is appended to the graphics queue (executed
  by the graphics thread), the audio queue (executed in the audio callback; the first entry after audio init marks the audio thread) or the
  destruction queue. `obs_in_task_thread(type)` is per-thread state. `obs_set_ui_task_handler(h)` stores the handler and queues a UI task
  that marks the calling-side UI thread through the handler.
* **S-042-R84** `obs_wait_for_destroy_queue`: returns false immediately unless both the video thread is initialised and audio exists;
  otherwise lets graphics and audio drain a marker task each and waits for the destruction queue; returns the queue's result.
* **S-042-R85** Callback lists (`tick`, `main render`, `main rendered`): add **inserts at the front**; remove erases the first entry equal in
  function *and* parameter; both under the draw-callback lock.
* **S-042-R86** Private data (`obs_data`): `obs_set_private_data(s)` clears the store then merges `s` (NULL clears only);
  `obs_apply_private_data(s)` merges `s` over the existing keys (NULL ignored); `obs_get_private_data()` returns the store with one more reference.

## 6. Algorithms

### 6.1 `obs_reset_video` (pseudocode)

```
fn reset_video(ovi):
    if core is null: return FAIL
    if any mix active: return CURRENTLY_ACTIVE
    if !size_ok(out) or !size_ok(base): return INVALID_PARAM          // size_ok: 2 <= v <= 32768
    stop video outputs; join graphics thread
    clear mix of every PUBLIC canvas                                    // D-4
    free all mixes, mutexes, group lists; drop queued graphics tasks
    ovi.out_w &= !3 ; ovi.out_h &= !1                                  // in place
    if no graphics device:
        err = create_device(ovi.module, ovi.adapter)
        if err: free_graphics(); return map(err)
        if !load_effects_and_textures(): free_graphics(); return FAIL
    log; profiler reset
    frame_interval  = muldiv(1e9, den, num); half = muldiv(5e8, den, num)
    recreate mutexes
    if !canvas_reset_video_internal(main, ovi): return FAIL
    for canvas in public_canvas_table (not main):
        if stored_info_valid(canvas) and !canvas_reset_video_internal(canvas, canvas.ovi): fail = true
    if fail: return FAIL
    start graphics thread; emit video_reset; return SUCCESS
```

### 6.2 GPU conversion tables (`gpu_conversion` honoured)

| I420 | `Planar_Y`, `Planar_U_Left`, `Planar_V_Left` | 1/w / 0 | w x h R8; w/2 x h/2 R8 x2 | same as textures |
| NV12 | `NV12_Y`, `NV12_UV` | 1/w / 0 | w x h R8; w/2 x h/2 R8G8 | same |

### 6.3 Name de-duplication

```
fn dedupe(table, name):
    if table has name:
        n = 2; loop { cand = name + " " + n; n += 1; if table lacks cand: return cand }
    return none
```

## 7. Concurrency

* Core tables are protected by recursive mutexes per table (`sources`, `outputs`, `encoders`, `services`, `canvases`, `displays`,
  `audio_sources`, `draw_callbacks`); enumeration holds the lock during callbacks; callbacks may re-enter the same table.
* The mix list has its own mutex; `obs_video_active`, `obs_canvas_video_active`, view add/remove/enum take it.
* A view's channels are protected by the view mutex; reference releases of replaced sources happen outside the lock.
* The graphics thread drains the graphics task queue (task mutex); the audio thread drains the audio queue inside its callback.
  `obs_queue_task` with `wait` from a foreign thread blocks on an event signalled by the owning thread.
* `render_display` runs on the graphics thread; `resize`/`update_color_space` may be called from any thread (draw-info mutex).
* Shutdown is single-threaded with respect to API users: no other API calls may race with it.

## 8. Reference defects and quirks

* **Q-1 (QUIRK, SHOULD match)** Output width/height 2 or 3 pass the size check and are aligned to 0 (width); the reset tears down first and fails
  with `FAIL` afterwards. Script `096_quirk_output_size_alignment`. A conforming implementation MAY validate the aligned size up front, but MUST
  then still return failure; the reference outcome (core left without video) SHOULD be kept.
* **Q-2 (QUIRK, MUST match)** Data paths are concatenated without separator. `014_data_paths`.
* **Q-3 (QUIRK, SHOULD match)** Rename warning prints the old name. `095_quirk_rename_warning_text`, `044`, `048`.
* **Q-4 (QUIRK, MAY differ in the warning)** Repeated audio reset re-declares the dedup signal (WARNING) and accumulates handler connections.
  `097_quirk_audio_reset_duplicate_signal`, `030`.
* **Q-5 (QUIRK, MUST match)** 32-bit unsigned wrap of `max_buffering_ms * samples_per_sec`. `031_reset_audio_edge` (`max_ms=100000` -> 10538 ms).
* **Q-6 (QUIRK, MUST match)** Canvas video reset neither validates sizes nor aligns; on failure the old mix is already gone and the invalid info is stored.
  `045_canvas_video`.
* **Q-7 (QUIRK, MUST match)** Colour-space refresh dropped when a resize is applied in the same render. `060_display`.
* **Q-8 (QUIRK, MUST match)** Levels are 0/0 until set once a device exists; defaults 300/1000 only without device. `029_video_signals_levels`.
* **Q-9 (QUIRK, SHOULD NOT leak)** Failure teardown of graphics forgets the premultiplied-alpha effect (+1 live graphics object).
  `099_quirk_graphics_leak` records the leak; also see failing mix creation in `027` (partially freed surfaces). Not required.
* **Q-10 (QUIRK, MUST match)** The graphics device and effects persist across resets; later `graphics_module`/`adapter` are ignored; effect
  failures in later resets do not occur. `024_reset_video_graphics_persist`.
* **Q-11 (QUIRK, MUST match)** `obs_view_render` drops removed sources without deactivating them. `050_views`.
* **D-1 (DEFECT)** `obs_shutdown` frees the copied command-line vector but leaves `argc` set and `argv` dangling; `obs_get_cmdline_args` after
  shutdown returns a dangling pointer and a later `obs_set_cmdline_args` is ignored. Required: shutdown resets the stored arguments to `{0, NULL}`
  (and then a new set succeeds). Demonstrated (count only) in `011_locale_version_cmdline` (`cmdline_argc -> 3` after shutdown).
* **D-2 (DEFECT)** `fps_num = 0` crashes `obs_reset_video` (SIGFPE in the interval computation, after teardown). Required: return
  `OBS_VIDEO_INVALID_PARAM` (the state after the call: torn down like any other post-validation failure is acceptable, but no crash).
  Probe lines in `021_reset_video_fps_format`.
* **D-3 (DEFECT)** `samples_per_sec = 0` crashes `obs_reset_audio2` (SIGFPE). Required: return false and leave no audio output.
  Probe lines in `031_reset_audio_edge`.
* **D-4 (DEFECT)** The canvas walks in `obs_free_canvas_mixes` and `restore_canvases` use the name-table link of a UUID-table head, skipping private
  canvases; their mixes are freed while the canvas keeps a stale mix pointer, they get no `video_reset`, and are not restored. Required: treat private
  canvases like public ones. `098_defect_private_canvas_video_reset`, `029`.
* **D-5 (DEFECT)** The reported/logged buffering milliseconds are computed in signed `int` and overflow for ticks > 2097 (UB). Required: 64-bit
  arithmetic (value `ticks * 1024 * 1000 / rate`, may exceed `i32`; report it truncated to `u32`). Not vectored (UB).
* **D-6 (DEFECT, precondition)** Several entry points dereference the core without checking (`obs_get_audio_info`, `obs_get_video_info`,
  `obs_shutdown`, `obs_reset_audio2` computes a member address of a NULL core before its check). Required for Rust: return the documented failure value
  (`false`/`FAIL`/no-op) when the core does not exist. The vectors only use `reset_video` / `reset_audio` before startup.
* **D-7 (DEFECT)** `obs_canvas_create_internal` leaks the canvas if context initialisation fails; `obs_display_destroy` may free a display never linked.
  Not observable; implementations must not leak.

## 9. Implementation notes (non-normative)

* Model the core as one `Core` struct behind `static CORE: Mutex<Option<Arc<Core>>>`, with each table in its own `parking_lot::ReentrantMutex<RefCell<..>>`
  (enumeration callbacks may re-enter). Use `IndexMap` for insertion-ordered name/UUID tables; `Vec` with `insert(0, ..)` for the head-insertion lists.
* The reference-count convention ("owners minus one") does not need to be reproduced in Rust (`Arc`), but the *observable* sequence of strong/weak
  semantics (`get_ref` after death returns None, weak upgrade) must hold.
* Keep graphics, audio output and hotkeys behind traits so the vectors' fakes can be reimplemented in the test runner.
* Signals in the vectors are produced by handlers connected through the generic signal handler of S-004; implement the same parameter names.
* Do not copy the leaks (Q-9) or UB (D-5).

## 11. Open questions and what is NOT specified

Not covered (no script, no rule or only a stub in the table above); implementers must not guess these from this spec:

1. **Registration functions** (`obs_register_source_s` etc., protocol list filling) - S-035. The vectors use a fake that mimics only the registry
   layout (id versioning, per-type arrays, order); `obs_get_latest_input_type_id` on an unknown id asserts in the reference.
2. **Graphics-thread frame loop** (`obs-video.c`), tick/draw/rendered callback *invocation*, frame timing, `obs_get_video_frame_time`, lag/skip counters,
   `obs_render_main_texture*`, `obs_get_main_texture`, `obs_get_active_fps`.
3. **Audio mixing loop**, audio monitoring (`obs_reset_audio_monitoring`, `obs_set_audio_monitoring_device`), `obs_enum_audio_monitoring_devices`.
4. **Source save/load and cross-source functions in obs.c**: `obs_load_source(s)`, `obs_save_source(s)`, `obs_save_sources_filtered`, `obs_apply_private_data`
   beyond R86, `obs_load_canvases` style helpers, source tick list, `obs_weak_source` family.
5. **Raw video/audio consumers**: `start_raw_video`, `stop_raw_video`, `obs_remove_raw_*_callback`, GPU encoding (`start_gpu_encode`, `obs_nv12_tex_active`, ...).
6. Hotkey thread internals, module unload order details beyond "unload modules before freeing data" (S-035).
7. Windows (COM init) and macOS specifics; the NVIDIA clear workaround in the display code (`use_clear_workaround`, Windows multi-GPU only).
8. `video_output_open`/`audio_output_open` threading behaviour (threads run in the vectors but their loops are not specified here), the resampler.
9. `obs_canvas_scene_create`, `obs_canvas_move_scene` (need real scene objects; S-033 covers scenes).
10. Mixes' `view` bookkeeping for *removed* canvases with active mixes.
11. Signed-overflow of reported buffering (D-5) and the NULL-core behaviours (D-6) have no vectors.
12. The **sufficiency check (a clean-room Rust implementation run against these vectors) was NOT performed** (explicit cost decision); the spec has therefore
    not been validated for completeness by an independent implementer.
